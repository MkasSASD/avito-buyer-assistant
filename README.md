# ИИ-помощник покупателя

Проект для хакатона ЮФУ 2026. Помогает подобрать комплект мебели и освещения по обычному текстовому запросу.

Пользователь описывает, что ему нужно. Программа извлекает из переписки основные условия — город, бюджет, категории товаров и требования к характеристикам — а затем ищет подходящие позиции в каталоге.

## Как это работает

1. Программа получает историю сообщений в формате JSON.
2. `src/extractor.py` извлекает из неё параметры запроса с помощью языковой модели.
3. Если для подбора не хватает данных, программа возвращает уточняющие вопросы.
4. `src/matcher.py` отбирает товары из каталога и собирает комплекты.
5. `src/formatter.py` формирует JSON-ответ.

Возможны три результата:

- `ok` — комплект или несколько вариантов найдены;
- `clarify` — нужно уточнить данные;
- `no_match` — подходящих товаров нет или бюджет слишком мал.

## Что умеет программа

- Разбирать запросы на естественном языке.
- Определять город, бюджет, категории и требования к товарам.
- Запрашивать недостающую информацию.
- Фильтровать каталог по заданным условиям.
- Подбирать до трёх вариантов комплектов.
- Сообщать, если собрать комплект не удалось.

## Как устроен проект

| Файл | Что делает |
| --- | --- |
| `main.py` | Принимает запрос, запускает обработку и выводит ответ |
| `src/extractor.py` | Извлекает требования из переписки |
| `src/matcher.py` | Фильтрует товары и собирает комплекты |
| `src/formatter.py` | Формирует ответы `ok`, `clarify` и `no_match` |
| `src/llm_client.py` | Отправляет запросы к API модели; содержит режим-заглушку |
| `src/config.py` | Загружает настройки и настраивает логирование |
| `data/` | Содержит каталог товаров, города и категории |
| `test_pipeline.py` | Проверяет основной сценарий работы |

### Использование языковой модели

Модель `google/gemma-4-31B-it` вызывается через API организаторов и используется только для извлечения требований в `extract_requirements` из `src/extractor.py`.

Сам подбор выполняется обычным кодом: программа фильтрует каталог, проверяет бюджет и собирает комплекты по структурированным данным. Описания товаров модели не передаются, поэтому текст из каталога не может выступать для неё инструкцией.

## Установка и запуск

### Требования

- Python 3.10 или новее.
- Дополнительные библиотеки Python не нужны — используется стандартная библиотека.
- В Linux скрипту `run` может потребоваться право на исполнение.

Если нужно, выполните:

```bash
chmod +x run
```

### Запуск

По умолчанию программа использует каталог `data/catalog.json`. Другой путь можно передать через `--catalog`:

```bash
./run --catalog /absolute/path/catalog.json < request.json > response.json
```

Входные данные читаются из `stdin`, результат записывается в `stdout`. В JSON-запросе должен быть непустой массив `messages`.

## Настройка API

Для обращения к модели задайте переменные окружения:

| Переменная | Назначение |
| --- | --- |
| `LLM_BASE_URL` | Базовый URL API-шлюза, без `/chat/completions` |
| `LLM_MODEL` | Название модели: `google/gemma-4-31B-it` |
| `LLM_API_KEY` | Индивидуальный ключ от организатора |
| `LLM_USER_AGENT` | Имя клиента, например `hackathon-team-01/1.0` |

## Локальный запуск без API-ключа

Для тестирования можно включить режим-заглушку:

```bash
LLM_API_KEY=mock
```

В этом режиме вместо обращения к API используется `_mock_llm_extract` из `src/llm_client.py`. Заглушка подходит для локальной проверки, но не заменяет работу с моделью при итоговой сдаче.

## Тесты

Запустить тесты можно командой:

```bash
LLM_API_KEY=mock LLM_BASE_URL=http://localhost python -m unittest test_pipeline -v
```
